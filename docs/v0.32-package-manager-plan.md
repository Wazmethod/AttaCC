# AttaCC v0.32 — Package Manager

Development branch: `feature/v0.32-package-manager`, based on `dev`. Version under development: `0.32.0-dev`.

## Goals

Keep package management practical for **Minecraft CC:Tweaked**, where an administrator should be able to distribute a multi-file app from the AttaCC Web repository, install or update it on a CC, and recover from an obvious failure without a production-grade deployment platform.

1. **Version by package.** Allow an optional `version` per package declaration. The manifest-level `version` remains a fallback for legacy packages. Show installed vs available version in `pkgctl status/show` and the Web catalogue. Do not break existing manifests.
2. **Predictable updates.** Download and validate all required files before replacing installed files; retain enough local backup information to restore an interrupted or failed install. Preserve `/etc`, machine identity, user data, and unrelated package files.
3. **Clean custom updates.** Permit authorized web-created app/module update by ZIP including file mapping and manifest modification in one action. Reject missing files, invalid Lua, unknown dependencies, duplicate destinations and unsafe ZIP paths.
4. **Custom presets.** Make installer/runtime discover declared `preset.*` packages (not only five hard-coded presets) and validate an associated executable entrypoint and app dependencies. Keep standard presets unchanged.
5. **Useful management commands.** Expose simple version comparison and install/upgrade status; no elaborate release infrastructure required.

## What stays out of scope

- Enterprise-grade signing, distributed transactions, cluster orchestration, complicated package lockfiles, or mandatory per-client accounts.
- Full sandboxing of arbitrary Lua; users install code from their own trusted AttaCC Web server.
- Mandatory GitHub connectivity; the Web repository is the primary source.

## Test map checklist

- New Advanced Computer installs a custom app and its module.
- Update changes one file, adds another and removes an obsolete file without corrupting shared files.
- Unknown dependency / missing file / malformed Lua: package rejected.
- Disconnect the Web server during transfer: existing program remains usable.
- Reboot while installing: `pkgctl` can report and recover.
- Two presets (native and custom) install and launch on distinct test computers.
- Workstation/SteamPlant and Master behave normally with existing `0.31` package registrations.
