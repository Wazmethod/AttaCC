# AttaCC 1.0.0 — Notes de publication (candidat)

**Statut :** préparation sur `release/v1.0.0-prep`, **non encore fusionnée sur `main`**.

AttaCC est une plateforme modulaire native CC:Tweaked/CraftOS. SteamPlant reste le nom de l'application du générateur, pas celui de la plateforme.

## Inclus dans la V1

- Runtime natif et presets SteamPlant, Master, Pocket, Workstation et Dashboard.
- Gestionnaire de packages `pkgctl` : installation, mise à jour, dépendances, versions individuelles, sources Web/GitHub et presets personnalisés.
- Backend Docker et AttaCC Web : supervision, Repository/App Store et WebBridge.
- Outils de configuration et diagnostics `logctl status`, `logctl errors`, `logctl tail`.
- Guide développeur et SDK intégrés à l'onglet **DOCS**, avec l'exemple `sdk-hello`.
- Pré-release : noms des packages npm renommés `attacc-web` / `attacc-web-backend`, tokens d'exemple refusés au démarrage, fichiers cachés exclus du Repository HTTP et contrôle NUL corrigé.

## Validation

L'utilisateur a confirmé que le Docker démarre et que deux CC sont opérationnelles après la recette. Les tests exhaustifs des cas de panne, de restauration, et de mise à jour sous interruption ne sont **pas certifiés automatiquement** par ce constat. Voir [recette](v1-release-test-plan.md) et [revue](v1-pre-release-review.md).

## Mise à jour depuis V0.34

1. Sauvegarder le dossier `web/data` et les packages ZIP customs.
2. Vérifier `MACHINE_TOKEN` et `ADMIN_TOKEN` personnalisés et distincts dans `web/.env`.
3. Déployer la branche/tag V1 dans Docker, sans `docker compose down -v`.
4. Vérifier la version du manifeste **effectivement servie** sous `/repo/packages/manifest.lua` : le Repository géré est persistant et peut garder l'ancien manifeste même après Git pull.
5. Importer la révision V1 dans le Repository seulement après sauvegarde des customs, si nécessaire.
6. Sur une CC de test : `pkgctl source test`, `pkgctl update core.runtime`, `pkgctl status`, `reboot`, `logctl status`.
7. Répéter progressivement sur les autres machines après validation.

## Limites connues

- `pkgctl` restaure les fichiers en cas d'échec d'écriture traité, mais n'a pas de transaction persistante anti-crash.
- Les versions et les métadonnées de certains fichiers historiques peuvent conserver des traces de versions antérieures ; la release V1 est identifiée par le manifeste et `version.json`.
- Le Repository Web persistant n'est pas automatiquement synchronisé avec le checkout Git.
- Le dépôt GitHub conserve temporairement le nom `steamplant-cc` ; renommage prévu **après le merge V1 sur main**, suivi de l'ajustement des URLs/constantes du bootstrap et des documentations.

## Publication proposée

Créer une PR depuis la branche de release vers `dev`, vérifier la CI/build et les derniers changements de version, puis merger vers `main` avec approbation explicite. Créer ensuite le tag `v1.0.0` sur le commit de main, puis renommer le dépôt GitHub.
