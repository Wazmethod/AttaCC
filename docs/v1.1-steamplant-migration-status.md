# AttaCC 1.1 — migration SteamPlant vers le SDK

Branche de travail uniquement. Ne pas installer sur une machine de production.

## Implémenté

- `core/io_catalog.lua` découvre des contrats matériels installés sous
  `lib/attacc_requirements_<id>.lua`, sans démarrer l'application.
- Le manifeste installe le contrat `steamplant`; `ioctl init` et
  `ioctl check` peuvent lire les rôles SDK avant la première publication.
- `ioctl init` conserve les méthodes, arguments, transformations et
  paramètres Redstone des bindings existants pendant leur réaffectation.
- La résolution matérielle ne réaffecte plus silencieusement un périphérique
  explicitement nommé lorsqu'il disparaît.
- `apps/steamplant/sdk.lua` déclare les données, graphes, commandes,
  vue générale et maintenance avec les primitives `lib.attacc`.
- Le module SteamPlant enregistre ses rôles et actualise les données du SDK
  parallèlement à son protocole existant. Le contrôleur conserve ses interlocks
  et sa logique de démarrage/arrêt.

## Limites actuelles — pas encore « full SDK »

1. Les méthodes des périphériques sont encore appelées dans
   `apps/steamplant/io.lua` par le code de contrôle historique.
2. L'initialisation I/O demeure partiellement liée à la configuration
   spécifique SteamPlant, notamment les embrayages Redstone.
3. Les commandes réseau passent encore par la logique du contrôleur et
   le protocole historique; il manque un chemin AttaCC générique et son
   mécanisme d'autorisation.
4. Le rendu local et certaines vues réseau conservent leurs anciens adaptateurs.
5. Le contrat SDK doit encore exposer toutes les variantes de commandes,
   tous les événements, protections et états, avant suppression des chemins
   hérités.

## Ordre de migration restant

1. Déclarer des rôles logiques de lecture et d'écriture pour chaque capteur,
   moteur et embrayage, puis configurer leurs méthodes et transformations.
2. Remplacer les appels matériels directs de SteamPlant par
   `app:read` / `app:write` ou les primitives I/O communes.
3. Introduire un transport de commandes AttaCC avec filtrage machine/réseau,
   identifiants de requête, anti-doublons, acquittements et autorisation;
   réutiliser le même dispatch local qu'en UI.
4. Remplacer les publications de télémétrie et d'événements historiques par
   les messages standard du SDK, avec compatibilité Master/Pocket/Web.
5. Migrer les vues et le cycle de vie vers le runtime SDK; supprimer le code
   spécifique devenant redondant.
6. Effectuer revue statique, contrôle des manifests et validations hors jeu.
7. **Seulement lorsque le portage complet est terminé**, organiser les tests
   sur les ordinateurs CC en vérifiant la parité fonctionnelle.

Ne pas présumer que les protections d'une machine sont garanties par
`requires` : cette option vérifie la présence matérielle, pas la sûreté d'une
commande ni l'authenticité de sa provenance.


## Migration lot: SDK I/O + network envelope (October 2026)

- SteamPlant sensor reads use `app:call(role, method, ...)`, resolved through
  the shared registry; motor `setSpeed`/`stop` use the same SDK API.
- Three clutch outputs use `app:write()` with role-specific inverted redstone
  mappings, and `app:read()` for physical output state.
- A shared SDK command dispatcher accepts `attacc.sdk.command.v1` envelopes
  and responds using `attacc.sdk.ack.v1`. It validates app, target, logical
  network, request freshness, origin, remote-enabled control and request ID.
  It caches results to avoid repeating identical accepted requests.
- SDK commands arrive on `sdkControl` (4257) with acknowledgements on
  `sdkAck` (4258); existing Master/Pocket command channels remain unchanged.
- **Remote execution is intentionally disabled** until real authenticated
  sender authorization exists. Any request on the SDK channel is rejected.
  The legacy protocol has not been authenticated or replaced by this work.

### Remaining work before full SDK

1. Introduce authenticated sender identities/capabilities, with a defined
   provisioning, revocation and replay-resistance model.
2. Migrate Master, Pocket and Web clients to send SDK envelopes, consume
   acknowledgements and discover SDK descriptors.
3. Move legacy UI events/telemetry and application lifecycle fully onto SDK.
4. Validate configuration and peripheral routing by offline test harnesses,
   then conduct final in-game parity tests only after full migration.
5. Retire legacy command handlers and I/O compatibility after verification.

Never enable remote actuator controls by merely allowing network names,
origin strings or matching computer IDs.
