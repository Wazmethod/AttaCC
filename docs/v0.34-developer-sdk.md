# AttaCC V0.34 — Developer SDK / Documentation

Branch: `feature/v0.34-developer-sdk` (from `dev`). Manifest/version: `0.34.0-dev`.

The developer SDK is **a documented way to use the existing CraftOS modules**, not a second runtime or a mandatory toolchain. It should remain easy to create a small app for Minecraft.

## SDK APIs actually available

### `lib.runtime` (see `core/runtime.lua`)
- `runtime.set(name, status, details)` stores the last status under `/run/attacc/state.json`.
- `runtime.snapshot()` reads all statuses.
- `runtime.log(component, level, message)` appends to bounded local logs.
- `runtime.logs(limit, component)` retrieves latest local entries, including rotated entries.

### `lib.bus` (see `core/bus.lua`)
- `bus.on(topic, handler)` registers a local event handler and returns a token.
- `bus.off(token)` removes a handler.
- `bus.emit(topic, payload, meta)` queues a local `attacc_bus` event.
- `bus.handle(event, topic, payload, meta)` dispatches events. You must call it from your application's event loop; emitting alone does not dispatch.

### `lib.protocol` (see `core/protocol.lua`)
- `protocol.findWirelessModem()` locates a wireless modem or returns nil.
- `protocol.send(modem, channel, message)` transmits a message.
- `protocol.makeModuleCommand(...)` constructs a command payload.
- `protocol.validateCommand(...)` optionally validates command shape/timestamps. It does **not** authenticate senders.

## Recommended package layout

```text
my-app.zip
  main.lua
  helper.lua
```

Publish via **Repository → Code & Import** as `app.my-app` version `1.0.0`. Map files to destinations that your `require` statements can resolve; declare `core.runtime` if using the APIs above.

For bootable apps: create a `preset.my-app` that depends on `app.my-app` and references its installed entrypoint. `pkgctl install preset.my-app` + `pkgctl activate preset.my-app` + `reboot`.
